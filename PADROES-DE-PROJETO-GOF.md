# Padrões de Projeto GoF no VinceArt

Resumo dos padrões criacionais, estruturais e comportamentais e de como aparecem no projeto.
“Uso relacionado” indica que há uma solução com intenção parecida, mas não necessariamente uma
implementação clássica do padrão GoF. “Não identificado” significa que não encontrei um exemplo
claro no código atual.

## 1. Padrões criacionais

| Padrão               | Resumo                                                                               | Uso no projeto                                                                                                                                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Singleton**        | Mantém uma única instância compartilhada de um objeto.                               | **Uso pelo framework:** providers registrados no NestJS usam o escopo singleton padrão, salvo configuração diferente. Não há uma classe Singleton implementada manualmente. Exemplo de registro de providers: [NotificationModule](src/modules/notification/notification.module.ts).                   |
| **Factory Method**   | Delega a criação de objetos a um método ou classe criadora especializada.            | **Uso relacionado:** há `useFactory` nos providers do NestJS e funções `create...` para montar dependências. São fábricas de composição; não encontrei a estrutura clássica em que subclasses redefinem o método de criação. Exemplo: [AssistanceModule](src/modules/assistance/assistance.module.ts). |
| **Abstract Factory** | Cria famílias de objetos relacionados por meio de uma interface comum.               | **Não identificado:** os módulos montam seus próprios providers, mas não encontrei uma fábrica que produza famílias intercambiáveis de objetos relacionados.                                                                                                                                           |
| **Builder**          | Monta um objeto complexo em etapas, normalmente com uma chamada final de construção. | **Uso claro em biblioteca:** a configuração do OpenAPI usa `DocumentBuilder`, encadeia opções e finaliza com `build()`: [bootstrap/http.ts](src/app/bootstrap/http.ts).                                                                                                                                |
| **Prototype**        | Cria um objeto novo copiando um objeto existente.                                    | **Não identificado:** não encontrei fluxo de criação de entidades por clonagem de protótipos.                                                                                                                                                                                                          |

## 2. Padrões estruturais

| Padrão               | Resumo                                                                                   | Uso no projeto                                                                                                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Adapter**          | Converte a interface de um componente para o contrato esperado pelo restante do sistema. | **Uso claro:** os repositórios Prisma implementam os contratos do domínio e traduzem chamadas e registros do ORM. Por exemplo, [PrismaArticleRepository](src/modules/article/infrastructure/prisma-article.repository.ts) implementa `ArticleRepository` e converte registros em objetos de domínio. |
| **Decorator**        | Acrescenta comportamento envolvendo um objeto que mantém a mesma interface.              | **Não identificado como padrão GoF:** `@Injectable()` e outros decorators do NestJS adicionam metadados ao código, mas não são wrappers que acrescentam comportamento a objetos.                                                                                                                     |
| **Facade (Fachada)** | Oferece uma entrada simples para um conjunto de operações internas.                      | **Uso explícito e central:** cada módulo expõe uma fachada pública que orquestra casos de uso. Essa decisão está no [ADR-0004](docs/ADR/0004-fachada-como-superficie-publica.md); exemplo de implementação: [CohortFacadeImpl](src/modules/cohort/application/cohort.facade.impl.ts).                |
| **Composite**        | Trata objetos individuais e grupos por meio do mesmo contrato.                           | **Não identificado:** não encontrei uma estrutura recursiva de componentes e grupos tratados uniformemente.                                                                                                                                                                                          |
| **Proxy**            | Controla ou intermedeia o acesso a outro objeto.                                         | **Não identificado claramente:** caches e providers de infraestrutura existem, mas não encontrei um proxy que preserve a interface de outro objeto para controlar seu acesso.                                                                                                                        |
| **Bridge**           | Separa uma abstração de suas implementações para que ambas variem de forma independente. | **Não identificado claramente:** as abstrações de provider permitem trocar integrações, mas não encontrei uma abstração e uma hierarquia de implementações organizadas como Bridge.                                                                                                                  |
| **Flyweight**        | Compartilha dados comuns entre muitos objetos para reduzir memória.                      | **Não identificado:** não encontrei objetos compartilhados por esse motivo.                                                                                                                                                                                                                          |

## 3. Padrões comportamentais

| Padrão                      | Resumo                                                                                            | Uso no projeto                                                                                                                                                                                                                                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Observer**                | Notifica assinantes quando um evento acontece.                                                    | **Uso claro:** [DomainEventBus](src/shared/events/event-bus.ts) oferece `publish` e `subscribe`; [CohortEventConsumer](src/modules/cohort/application/cohort-event.consumer.ts) assina o evento `InvitationAccepted`. O projeto usa também o estilo publicação/assinatura.                                                     |
| **Strategy**                | Permite trocar uma implementação de comportamento mantendo o mesmo contrato.                      | **Uso claro, com uma implementação HTTP registrada atualmente:** os casos de uso dependem de abstrações como [EmailDeliveryProvider](src/modules/notification/domain/ports/email-delivery-provider.ts) e [AssistanceProvider](src/modules/assistance/domain/ports/assistance-provider.ts), implementadas pelos providers HTTP. |
| **Command**                 | Encapsula uma operação como objeto para que possa ser passada, enfileirada ou executada depois.   | **Não identificado como padrão GoF:** tipos como `CreateCohortCommand` são dados de entrada; a operação fica em outra classe, como [CreateCohortUseCase](src/modules/cohort/application/create-cohort.use-case.ts). O nome `Command`, sozinho, não caracteriza o padrão.                                                       |
| **State**                   | Muda o comportamento de um objeto conforme seu estado, geralmente com objetos de estado próprios. | **Não identificado:** há entidades com campos de status e regras de transição, mas não encontrei comportamentos distribuídos em classes de estado intercambiáveis.                                                                                                                                                             |
| **Template Method**         | Define a sequência de um algoritmo e deixa etapas específicas para subclasses.                    | **Não identificado:** o recurso de “templates” de artigos é uma funcionalidade do domínio e não implementa esse padrão.                                                                                                                                                                                                        |
| **Iterator**                | Percorre uma coleção sem expor como ela é armazenada.                                             | **Não identificado como padrão próprio:** o código usa as iterações nativas de TypeScript/JavaScript, sem um iterador customizado para uma coleção.                                                                                                                                                                            |
| **Chain of Responsibility** | Encaminha uma solicitação por uma sequência de handlers, até que um deles a trate.                | **Não identificado como estrutura própria:** o NestJS possui guards e middleware no ciclo HTTP, mas não encontrei uma cadeia de handlers de negócio implementada segundo esse padrão.                                                                                                                                          |
| **Mediator**                | Centraliza a comunicação entre componentes para reduzir referências diretas entre eles.           | **Uso relacionado:** o [DomainEventBus](src/shared/events/event-bus.ts) centraliza a entrega de eventos. No código, seu papel mais direto é o de Observer/publicação-assinatura; não há um mediador dedicado coordenando interações entre objetos.                                                                             |
| **Memento**                 | Registra um estado anterior para permitir sua restauração.                                        | **Uso relacionado claro:** o módulo de artigos persiste versões do conteúdo e permite restaurá-las. [RestoreVersionUseCase](src/modules/article/application/editing.use-cases.ts) recupera uma versão e cria um novo registro de restauração; o conceito é semelhante a Memento, embora não haja uma classe chamada `Memento`. |
| **Visitor**                 | Adiciona operações a uma estrutura de objetos sem alterar as classes dessa estrutura.             | **Não identificado:** não encontrei visitantes percorrendo uma estrutura de elementos de domínio.                                                                                                                                                                                                                              |
| **Interpreter**             | Representa e avalia expressões de uma linguagem ou gramática.                                     | **Não identificado:** não encontrei uma linguagem de domínio com expressões interpretadas por uma árvore de regras.                                                                                                                                                                                                            |

## Resumo

Os usos mais claros no código são **Facade**, **Adapter**, **Observer**, **Strategy** e **Builder**.
Há usos relacionados a **Singleton** pelo ciclo de vida padrão dos providers do NestJS e a
**Memento** pelo versionamento e restauração de artigos. O NestJS também oferece providers com
`useFactory`, mas isso não significa, por si só, que o projeto use o Factory Method GoF clássico.
